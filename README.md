# MedPay Automation MVP

Streamlit-приложение для автоматизации обработки прайс-листов медицинских клиник с матчингом к каталогу MedPay.

## Быстрый старт

```bash
# 1. Клонируйте или распакуйте проект
cd medpay_automation

# 2. Создайте виртуальное окружение
python -m venv venv
source venv/bin/activate      # Linux/macOS
# venv\Scripts\activate       # Windows

# 3. Установите зависимости
pip install -r requirements.txt

# 4. Запустите приложение
streamlit run app.py
```

Приложение откроется на `http://localhost:8501`

## Рабочий процесс

1. **Загрузить каталог MedPay** — Excel-файл с колонками: `ID number`, `Name RU`, `Name UZ`, `type`, `Name KR`
2. **Загрузить HTML прайс-лист клиники** — сохранённая страница с сайта клиники или Med24
3. **Проверить извлечённые услуги** — редактировать/удалять строки при необходимости
4. **Запустить матчинг** — автоматическое сопоставление с каталогом
5. **Проверить результаты матчинга** — исправить ID, цены, типы вручную
6. **Скачать итоговый файл** — `ready.xlsx` с ровно 22 колонками

## Правила обработки

### Типы услуг
- `Анализы` — лабораторные исследования (кровь, моча, кал, мазок, ПЦР и т.д.)
- `Диагностика` — инструментальные исследования (МРТ, КТ, УЗИ, рентген, ЭКГ и т.д.)

### Цены
- Числовые: только цифры без пробелов и запятых (`350000`)
- Если не найдена: `По запросу`

### ID
- Только из каталога MedPay
- Если нет совпадения (уверенность < 85%): `-`

### Итоговый файл (22 колонки)
```
Услуга ID | Клиника | Филиал | Имя RU | Имя UZ | Имя KR |
Описание UZ | Требования UZ | Требования RU | Требования KR |
Тип услуг | Цена | Описание RU | Описание KR |
Продолжительность (минут) | Активен |
Категория RU | Категория UZ | Категория KR |
Код уз | Код ру | Код лаборатория
```

```python
assert len(df.columns) == 22
assert set(df["Тип услуг"].unique()).issubset({"Диагностика", "Анализы"})
assert all(df["Активен"] == "TRUE")
assert all(df[["Код уз", "Код ру", "Код лаборатория"]].isna() | 
           (df[["Код уз", "Код ру", "Код лаборатория"]] == ""))
```

## Ограничения

- HTML-парсер работает лучше на структурированных страницах с таблицами
- Матчинг основан на текстовом сходстве; семантический поиск (sentence-transformers) опционален
- При слабом совпадении (<85%) ID не назначается — требуется ручная проверка
- Максимальная скорость матчинга: ~500 услуг/мин

## Следующие улучшения

1. **Semantic matching** — добавить sentence-transformers для улучшения матчинга медицинских терминов
2. **SQLite кэш** — сохранять результаты матчинга между сессиями
3. **Batch HTML** — обработка нескольких HTML файлов за раз
4. **Шаблоны клиник** — сохранять настройки парсинга для конкретных сайтов
5. **API интеграция** — прямая загрузка в MedPay через API
6. **Аудит-лог** — история всех изменений с timestamp
